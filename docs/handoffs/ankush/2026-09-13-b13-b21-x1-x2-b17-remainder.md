## B13 — cost-centre controls and delegation of authority

Two new tables (migration `b4f7c9a1e3d2`):
- `CostCentre` (code, name, budget_holder_id, annual_budget_usd, active) —
  `app/services/cost_centre_service.py`.
- `DelegationGrant` (grantor/delegate/scope/campaign_id/window/revoked_at) —
  `app/services/delegation_service.py`.

`app/api/approvals.py`'s cost-centre route now calls `cost_centre_service.validate()` before
moving anyone: an unknown code, a closed cost centre, or a claimed budget holder who does not
match the registry are all refused (422), and the registry's own `budget_holder_id` — not the
caller's claim — becomes the record's owner. `CandidateLifecycle.cost_centre_id` (new column)
stores which budget a hire is against, carried forward on later transitions the same way
`campaign_rank` already is (`lifecycle_service._write`).

All three write routes (`request`, `cost-centre`, `grant`) now accept an optional
`on_behalf_of_id`. When present it is checked against `delegation_service.require_delegation()`
— an active, unrevoked `DelegationGrant` for the "approval" scope, either global or scoped to
the campaign — before the move is made, and the resolved id is passed through to
`lifecycle_service.transition(..., on_behalf_of_id=...)`, which already had the column
(`LifecycleTransition.on_behalf_of_id`) but nothing checking it.

New admin endpoints: `POST /api/cost-centres`, `GET /api/cost-centres`,
`POST /api/cost-centres/{code}/close`, `POST /api/delegations`, `GET /api/delegations`,
`POST /api/delegations/{id}/revoke`.

**Broke and fixed three pre-existing tests as a direct, expected consequence**: three
`test_approvals_api.py` tests and one `test_recruitment_360_journey.py` test posted to
`/cost-centre` with a code (`CC-410`) that existed nowhere — exactly the behaviour B13 was
supposed to stop accepting. Updated all four to seed a real `CostCentre` first, via a new
`cost_centre` fixture in `test_approvals_api.py` and an inline `POST /api/cost-centres` call in
the journey test. `tests/test_cost_centre_delegation.py` (new): 11 tests covering registry
validation, closed-centre refusal, delegation grant/revoke, and an unauthorized
`on_behalf_of_id` claim being refused.

## B21 — FinOps: LLM cost instrumentation and `/api/developer/metrics`

`web/developer.html` was already calling `GET /api/developer/metrics`; that route did not
exist anywhere in `app/`, and no LLM call was instrumented for tokens at all — worse than the
backlog doc's "tokens and runtime exist" line claimed.

Built:
- `app/core/llm_provider.py`: `get_chat_model()`/`get_cached_chat_model()` now return an
  `_InstrumentedChatModel` wrapper (forwards everything via `__getattr__`, records usage after
  `.invoke()`). This is the one seam every agent call site already goes through — chosen over
  editing each of the ~14 call sites across 10 files individually.
- `app/core/llm_usage.py`: a `contextvars`-based `track(db, campaign_id=, run_id=, call_type=)`
  a call site opens around a block of work; `record()` reads the open context and writes an
  `LLMCallLog` row. A call made with no `track()` open is silently not recorded — same rule
  `AuditEvent` already follows. Handles both the new `usage_metadata` and the older
  `response_metadata["token_usage"]` shapes.
- `LLMCallLog` (new table, migration `b4f7c9a1e3d2`): campaign_id, run_id (nullable — null for
  a JD-extraction call made before any run exists), call_type, model_name, token counts,
  estimated cost.
- `requirement_service.extract_and_store_requirements` and `evaluation_service.execute_run`
  are the two call sites wired up (`call_type="jd_extraction"` / `"screening"`).
- `app/core/pricing.py`: two sources — an explicit configured rate
  (`azure_openai_input_cost_per_1m`/`_output_cost_per_1m`, new settings) or a bundled,
  last-verified Azure OpenAI retail fallback. **Deliberately no live call to the Azure Retail
  Prices API** — see `docs/DECISIONS.md` for why (test/offline-box reachability).
- `app/api/developer.py`, `GET /api/developer/metrics`: serves the exact shape
  `web/developer.html` already reads, plus the rest of B21's calculation contract —
  `operating_cost_to_date_usd`, `cost_per_candidate_usd`, `projected_cost_10000_cvs_usd`
  (the "10,000-CV scenario"), and an additive `campaign_costs` array — all computed from real
  `LLMCallLog` rows, not the hand-measured constants the backlog table lists.

`tests/test_developer_metrics.py` (new): 11 passed — pricing fallback/configured paths, both
usage-metadata shapes, context leakage, and the metrics endpoint's aggregation (empty state,
run+campaign aggregation, an in-progress run). No real LLM call is exercised in tests (every
existing test mocks `parse_jd` directly, and `LLM_ASSISTED` runs mock
`scoring_agent.refine_criterion_scores`) — instrumented end-to-end behaviour was checked with a
`MagicMock` client in the terminal, not a pytest test, and reported honestly as such.
`web/developer.html` rendering these new fields correctly in a browser was **not** verified —
that screen is Subhadeep's file.
